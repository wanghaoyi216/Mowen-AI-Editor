## 一、项目概述

### 1.1 项目定位

**Novel AI Editor** 是一个全链路自动化 AI 小说创作系统，旨在通过 AI 驱动的方式实现从关键词生成到章节导出的完整小说创作流程。系统支持全自动模式和人工确认模式，用户可以根据需求灵活切换。

### 1.2 核心价值

| 价值点 | 描述 |
|--------|------|
| **全链路自动化** | "关键词生成→热点扫描→世界观构建→剧情规划→章节写作"全流程自动触发 |
| **Human-in-the-Loop** | 支持多阶段确认模式，用户可在关键节点介入审核 |
| **AI 创作多样性** | 双 AI 协作 + 向量数据库反重复检测，避免内容同质化 |
| **大屏指挥中心** | 单一高级可视化界面，全面覆盖 AI 执行流程与数据洞察 |

## 二、用户画像

### 2.1 目标用户

| 用户类型 | 特征 | 核心需求 |
|----------|------|----------|
| **网络小说作者** | 日更压力大，需要快速产出 | 全自动生成章节草稿，减少创作负担 |
| **内容策划师** | 需要热点分析和趋势洞察 | 热点扫描、趋势分析、关键词挖掘 |
| **AI 技术爱好者** | 喜欢探索 AI 能力边界 | 自定义工作流、调整 AI 参数、查看执行日志 |

| **右侧确认面板** | Human-in-the-Loop 确认界面（确认模式）/ 自动状态展示（自动模式） | ✅ 已完成 |

## 四、非功能需求

### 4.1 性能要求

| 指标 | 目标值 | 备注 |
|------|--------|------|
| API 响应时间 | < 500ms（非 AI 请求） | AI 请求受模型响应时间影响 |
| 前端首屏加载 | < 2s | 使用 Vite 构建，代码分割 |
| 数据库查询 | < 100ms | 使用 PostgreSQL + 索引优化 |
| Redis 缓存命中 | > 80% | 上下文缓存、Token 统计 |

### 4.2 AI 上下文管理

| 策略 | 描述 | 参数 |
|------|------|------|
| **分层记忆** | 持久层 + 摘要层 + 活跃层 | 持久层 3000 tokens，摘要层 5000 tokens，活跃层 10000 tokens |
| **Token 预算** | 总上下文不超过 32,000 tokens | 自动裁剪低优先级内容 |
| **语义检索** | 向量数据库 Top-K 检索 | K=5，基于章节 embedding |
| **记忆衰减** | 较久远章节仅保留摘要 | 滚动窗口，最多 30 章摘要 |

### 4.3 安全性

| 措施 | 描述 |
|------|------|
| **API Key 管理** | OpenRouter API Key 通过环境变量配置，不暴露到前端 |
| **CORS 限制** | 仅允许 `*`（开发环境），生产环境应配置具体域名 |
| **数据库隔离** | Docker 内部网络，仅后端容器可访问数据库 |
