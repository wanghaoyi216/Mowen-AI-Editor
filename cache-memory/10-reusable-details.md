# 可复用细节

## AI 执行规则

1. 先 Plan，后 Execute。
2. 每次任务都要做上下文抽取。
3. 输出必须可回溯到任务或资料来源。
4. 每轮完成后必须写实施记录，方便后续 AI 直接接力。

## 工程规则

1. 先后端结构，后前端页面。
2. 先数据模型，后 AI 能力接入。
3. 每完成一个功能，同步更新 `cache-memory`。
4. 空仓首轮优先交付“可运行骨架 + 结构化文档 + 下轮提示词”。
5. 对复杂创作系统，任务流至少拆到 `project_id + module_type + chapter_id + task_step` 粒度。
6. 图谱接口开发期建议采用 `neo4j-primary + sqlite-fallback` 模式。
7. 真实工程推进时，优先形成 `frontend + backend + postgres + neo4j + redis` 的稳定容器组合。
8. 任务执行系统建议从第一版开始采用 `persistent history + ephemeral runtime` 双层存储模型。
9. ReAct 系统的步骤运行态建议使用 Redis Hash，以 `step_no` 为 field。
10. 在接真实模型前，先完成任务-步骤-运行态-图谱之间的最小执行链。
11. 搜索与抓取类工具统一通过后端服务封装，避免前端直接持有密钥。
12. 搜索结果先映射为结构化创作资产，再进入章节生成链路。
13. 对 OpenRouter 这类动态模型池，优先使用“运行时免费模型发现 + 偏好关键词轮询”策略。
14. 章节工作流建议采用“资产摘要 -> 章节设计 -> 正文生成”的三段式结构。
15. 在章节工作流里，建议优先使用“任务化设计/生成”，再补直接调用型接口作为辅助。
