# 问题记录

## 2026-05-31

### 问题 1

PowerShell profile 存在额外噪音输出，影响命令结果可读性。

### 分析

本机 profile 中调用了缺失的 `starship`，导致每次带 profile 的命令产生错误文本。

### 处理

后续 shell 执行统一优先使用 `login=false`。

### 问题 2

后端导入验证失败，原因是本地 Python 环境尚未安装 FastAPI 依赖。

### 分析

代码骨架本身尚未证明有语法问题，但运行验证依赖于先安装 `backend/requirements.txt`。

### 处理

顺序执行后端依赖安装，再做导入与接口验证。

### 问题 3

前端构建时 `tsc` 未找到。

### 分析

这不是 TypeScript 配置问题，而是 `npm install` 尚未完成导致本地 `node_modules/.bin/tsc` 不存在。

### 处理

顺序执行 `npm install` 后重新构建。

### 问题 4

前端 JSX 中直接写 `->` 导致 TypeScript/JSX 解析错误。

### 分析

在 JSX 文本节点中，`>` 可能触发错误解析，尤其在某些上下文中。

### 处理

将箭头表示改为普通短横线描述，避免语法歧义。

### 问题 5

演示种子脚本首次运行时无法导入 `app` 包。

### 分析

直接执行 `backend/scripts/seed_demo.py` 时，Python 模块搜索路径默认不包含 `backend/` 根目录。

### 处理

在脚本中显式补充项目根路径到 `sys.path`。

### 问题 6

图谱查询需要在新增关系表后先完成建表，否则旧数据库文件会缺少新表。

### 分析

当前项目尚未接入迁移工具，新增 ORM 模型后依赖 `create_db_and_tables()` 自动补表。

### 处理

在脚本和验证流程中显式先执行建表，并将“引入迁移工具”作为后续优先项。

### 问题 7

当前项目虽然已经支持 PostgreSQL 依赖，但数据库模式管理仍然依赖 `create_all()`。

### 分析

这适合原型，不适合长期演进的真实项目。随着表数量增加，缺少迁移会导致环境一致性和升级困难。

### 处理

已加入 Alembic 依赖，并将初始化迁移体系列为下一优先级。

### 问题 8

为了给 Alembic 加统一模型导入，初版实现触发了 `Base` 的循环依赖。

### 分析

在 `base.py` 顶层导入模型聚合模块时，模型文件又回头导入 `Base`，形成初始化环。

### 处理

将模型聚合导入移动到 `create_db_and_tables()` 内部，避免顶层循环依赖。

### 问题 9

新增依赖安装完成前后的命令结果混杂，容易误判为代码问题。

### 分析

在长时间安装完成前后的并行命令中，旧错误输出可能掩盖最新状态。

### 处理

安装依赖后单独重复关键导入与 Alembic 验证，确认最终状态。

### 问题 10

图谱如果长期只停留在角色关系层，无法支撑故事主线、事件链和章节影响分析。

### 分析

小说系统真正需要的是混合图谱，而不是单一社交图。

### 处理

本轮把图谱 fallback 扩展到了 PlotLine、StoryEvent、Chapter。

### 问题 11

前端 JSX 中出现 `角色 -> 事件` 这样的文本时，会再次触发 `>` 解析问题。

### 分析

该问题不是局部偶发，而是 JSX 文本中所有箭头文本都存在风险。

### 处理

前端文案统一避免直接使用 `->`。

### 问题 12

Requests 相关依赖在当前本机环境中存在版本告警噪音。

### 分析

这是当前 Python 环境中的全局依赖兼容性问题，不是本项目逻辑错误，但会影响命令输出整洁度。

### 处理

当前先记录为环境噪音，后续如果需要可通过独立虚拟环境或容器执行来隔离。
