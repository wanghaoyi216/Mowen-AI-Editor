# 经验积累

## 2026-05-31

1. 空仓项目更适合先建立“计划-设计-执行-沉淀”的固定框架。
2. 对 AI 创作类项目，结构化数据建模优先级高于文本生成能力接入。
3. `cache-memory` 必须从第一天开始维护，否则后续 AI 接力成本会迅速上升。
4. 对多技术栈空仓项目，最合理的第一轮交付是“文档基线 + 最小运行骨架”，而不是试图一次性做完整业务。
5. 图谱接口应尽早占位，否则后续前后端和 AI 编排层的边界会反复变化。
6. 对 AI 工作流系统，任务流隔离维度必须先于生成器实现落地，否则状态管理会失控。
7. 热点探索模块不应作为附属功能，它直接影响选题、标签、角色与剧情规划的质量。
8. 图谱模块在开发期必须具备降级策略，否则 Neo4j 的环境依赖会拖慢整个系统推进。
9. 先做“角色图谱闭环”是合理顺序，因为它最能验证数据库、图谱、前端和任务流之间的连接方式。
10. 对“真实项目”要求，基础设施层必须尽早进入版本控制，而不是留到业务写完再补。
11. Redis 即使暂时未接任务执行器，也应该先纳入编排，因为 AI 工作流系统几乎必然需要异步执行和状态流转。
12. Alembic 的引入不只是技术洁癖，它是多环境部署和长期迭代的必要前提。
13. AI 任务系统最稳妥的基础模型是“关系库存历史，Redis 存瞬时运行态”。
14. ReAct 执行器的真正可视化基础不是任务列表，而是步骤运行态。
15. 小说创作图谱必须尽早从“人物图”升级到“人物 + 剧情线 + 事件 + 章节”的混合图。
16. Character -> Event 参与关系是把“人物系统”和“剧情系统”真正接起来的关键边。
17. 对复杂 AI 系统，先做“最小可执行链”比直接接模型更稳妥。
18. 联网搜索能力接入后，系统才真正开始具备“自动探索题材与资料”的基础。
19. 搜索集成必须从第一天就采用“环境变量注入，不回显密钥”的纪律。
20. “趋势结果 -> 创作资产”的转换是 AI 小说系统真正有生产力的关键节点。
21. 在复杂生成系统里，先做规则映射打通主链路，往往比一开始上重模型更稳。
22. OpenRouter 这类统一网关非常适合作为项目主调用层，因为模型池变化比项目代码快。
23. 免费模型选择必须是运行时发现，而不是静态配置。
24. 章节生成前增加“设计层”是必要的，这会明显降低正文漂移风险。
25. 对长链路创作系统，资产摘要是非常关键的中间表示。
26. 章节链一旦任务化，后续修订、校验、重试和日志都会容易很多。
27. 图谱服务里的边生成逻辑很容易因为循环层级出错，必须在每次深化图谱时仔细验证。
